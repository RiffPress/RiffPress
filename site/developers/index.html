Built to be extended

Riff is built the way a feature plugin is: one track shape everywhere, read through WordPress's own APIs, with a public surface that is written down and kept. Everything below is stable within a major version.

PHP

Every filter and action has a page of its own, generated from the docblock above the line it fires on, and CI fails a change that adds one without it. The PHP reference lists them with the Riff\Source interface, the track schema and the Listen block. Set the accent, add chips under Now Playing or controls to the bar, redraw a cover, or turn the player off on a page; all hooks are searchable in one list.

JavaScript

window.riff is the player's API. Actions and filters through wp.hooks, and riff:* events on the player's root, announce every change of state: what is playing, what is queued, what a press did. The JavaScript reference has every member of window.riff, generated from the player's own docblocks, and each action and filter has a page in the hooks reference.

REST and GraphQL

The REST API gives each audio and video item in wp/v2/media a riff_track. riff/v1/library lists the posts with tracks and riff/v1/library/{id} opens one with its tracks and rendered blocks; both describe themselves on OPTIONS. With WPGraphQL active, MediaItem.riffTrack and Post.riffTracks. The REST API shares one schema with the player, Riff\Tracks::schema(), versioned and held to after the riff_track filter; WPGraphQL's RiffTrack carries most of it. The REST API reference has every route, argument and field.

Your own tracks

Tracks come from registered sources. The core source reads the audio, video and playlist blocks in posts. A plugin adds its own post type or catalogue by implementing Riff\Source and calling Riff\Sources::register() on init, or through the riff_sources filter, and the library, the REST routes and the player read it like any other. The PHP reference has the interface, method by method.

Theming

The player and the Listen block expose custom properties, --riff-accent, --riff-bg and the rest. A theme sets the accent under settings.custom.riff.accent in theme.json; any plugin can through riff_accent. The CSS reference lists each public property with its default.

Under the hood

Each browser API and CSS feature the player calls has a page of its own: how Riff uses it, why, what happens without it, and the exact lines in the source at the commit that was published.

The code

No build step: the shipped files are the source. The repository has the contributing guide, the test suites, and a Playground blueprint for a scratch site with the demo on it.
